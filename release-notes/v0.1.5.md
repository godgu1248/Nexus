# Nexus 枢纽 v0.1.5

这一版只做三件事：堵一个能被利用的洞、修一个能把管理员锁死的竞态、顺手把两处热点变便宜。

## 安全

- **伪造 `X-Forwarded-For` 可以完全绕过登录限速**（已修复）。
  nginx 用 `$proxy_add_x_forwarded_for` 把客户端自带的头原样保留、真实地址追加到末尾，
  而应用取的是最左边那一段——限速键 `{ip}|{username}` 于是完全由攻击者决定。
  现在优先读 `X-Real-IP`（nginx 覆盖写，伪造不了），退到 `X-Forwarded-For` 的最后一段，
  并且用 `IpAddr::from_str` 校验（`abc` 这种值不再被当成 IP 写进审计）。
  修复前后都用同一套 A/B 脚本在生产复测：修复前伪造组 8 次不锁，修复后第 6 次锁定。

- **「最后一个管理员」不再是先查后改**：`change_role` / `change_status` / `delete_user`
  原来在事务外读计数，两个管理员同时降级对方可以把管理员降到 0，且界面无法恢复。
  现在计数与写入在同一事务内，并对 active admin 行 `FOR UPDATE`。

## 性能

- 档案列表的 `ORDER BY` 复用 `like_count` 别名，每行少一次关联子查询。
- 内存会话上限 2 万 → 5 千：淘汰时要持锁排序，正常用量远低于此，没必要为不存在的容量付延迟。

## 验证

`cargo test` 261 项全绿，`clippy -D warnings` 与 `fmt --check` 均 0；线上 smoke 19/19。
审查方法、被实测推翻的假设、以及记录但没改的项都在 `DESIGN.md §37`。
