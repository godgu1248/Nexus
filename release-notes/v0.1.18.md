# Nexus 枢纽 v0.1.18

自查上一版配色改动留下的四个问题。

## 1. 两处引用了不存在的 token

`.richtext` 与 Word 查看器的次要文字写成 `color: var(--muted, var(--text-dim))`——
`--muted` 从来没有定义过，兜底让颜色看着是对的，所以一直没人发现。已统一改成 `var(--text-dim)`。
这是用静态审计扫"被引用但没定义"的 token 才暴露的。

## 2. 首屏会闪一下浅色控件

`color-scheme` 只声明在 `body.theme-*` 上，而主题 class 要等 `<body>` 解析到才生效；
`<head>` 到 `<body>` 之间，滚动条与表单控件按浏览器默认（浅色）画。`:root` 现在声明
`color-scheme: dark`（与默认主题一致），浅色主题再由 `body.theme-paper/sand` 覆盖。

## 3. 改 CSS 其实需要重编

`?v=` 写在模板里，模板被 Askama 编译进二进制——只推 `static/` 的话页面还指着旧的版本号，
而 nginx 对 `/static/*` 发一年 `immutable`，老访客永远拿不到新样式。所以这一版同时重编了二进制
并把缓存键升到 `20261102`。彻底解耦要把版本号改成运行时配置，代价是给 30 多个页面结构体各加一个字段，
先记为债务。

## 4. 验收

- 对比度审计：10 套配色 × 7 组配对（正文/次级/弱化文字压在底与卡面上、强调色当链接）全部达标。
- 端到端：登录 → `/settings` 数出 **10 张色卡** → 提交 `theme=paper` → 首页 `<body class="theme-paper …">`
  → 切回 `ink` → `<body class="theme-ink …">`，两步都 303 且 class 正确。
- `ops/smoke.ps1` **20/20**；`cargo test` 312 passed；clippy 与 fmt 干净。
- 生产：`restart: active`、`healthz 200`、`cache key: app.css?v=20261102`，
  三份静态哈希本地=远端。
