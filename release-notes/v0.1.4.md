# Nexus 枢纽 v0.1.4

这一版不改功能，只做代码审查后的修复与性能/兼容性优化。适用升级：直接替换二进制重启即可，迁移 `0014` 会在启动时自动执行。

## 修掉的四个真问题

1. **会话存储无界增长（公网可触发）**
   原来的 `tower-sessions-memory-store` 只把过期会话过滤掉、从不删除，而每个匿名访客都会因为签发 CSRF 落一条记录——扫一遍全站就能让内存只增不减。
   现在换成自带的 `BoundedStore`：2 万条上限、60 秒清扫、读到过期即删、超限按到期时间淘汰最旧的。`tower-sessions` 关掉 `memory-store` 默认特性，该 crate 不再参与编译。

2. **审计表缺 `created_at` 索引**
   管理页默认视图是 `ORDER BY created_at DESC, id DESC LIMIT 20`，而原有三条索引没有一条以 `created_at` 打头。
   新增 `idx_audit_created (created_at, id)`。5,338 行实测：5,448 行全表 + `filesort`（3.18 ms）→ 20 行反向索引扫描（0.45 ms），**7.1 倍**，差距随表增长放大。

3. **登录失败计数表"满了就清空"是锁绕过口子**
   原本 4,096 条上限一到就整体清空，等于把"对目标账号 5 次/5 分钟"和"对自己 IP 20 次/5 分钟"的锁同时归零——换着用户名填满表即可重置。
   改成按最早创建时间淘汰四分之一，内存照样有界，但最近的计数留着。

4. **兼容性两处**
   - `color-mix()` 补固定色回退：Chromium 111 / Safari 16.2 之前该函数不被识别，整条自定义属性判无效，光晕会直接消失而不是变淡；
   - 静态资源版本号跟着 CSS 走（`app.css?v=20261026`）：nginx 对 `/static/*` 发一年 `immutable`，改了样式不换 URL，老访客一年看不到更新。

## 一个假设被实测否定，所以撤回

审查时判断 `(? IS NULL OR a.actor_id = ?)` 这种 catch-all 写法会让索引失效，据此把审计查询改成动态拼接 SQL + `AssertSqlSafe`。实测（同一会话内 `PREPARE` + 全 NULL + `EXPLAIN`）显示 MySQL 8.0.46 的两种写法计划完全一致，都走 `idx_audit_created` 反向扫描——没有收益，却引入一个"我保证安全"的逃生舱，破坏「SQL 一律字面量」的不变式，于是完整撤回，只保留索引。

## 验证

- `cargo test` **258 passed / 0 failed**；`clippy -D warnings` 与 `fmt --check` 均 0。
- Linux 产物为 musl 全静态（`readelf` 无 `PT_INTERP`），Windows 产物解压即跑；空环境下都以退出码 1 提示「缺少必需的环境变量 DATABASE_URL」。
- 线上冒烟 19/19，迁移 14 条全部 success。

## 已知取舍（记录在 DESIGN §36.5）

档案搜索仍是 `LIKE '%q%'`（两份统计各扫一次表）、浏览量每次打开都写一行、指派下拉不带 LIMIT——都按当前团队规模接受，等量级变化再动。
