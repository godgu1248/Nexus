## 修复

- **迁移文件不可变**：v0.1.0 误改过 `0002_forum.sql` 与 `0005_tasks.sql` 的注释，导致新版本二进制对已有数据库拒绝启动（`migration 2 was previously applied but has been modified`）。已把它们逐字节还原到 `8c17d76` 的版本。**升级到本版本即可正常启动**；如需从 v0.1.0 升级，请直接用本包替换二进制。
- **档案列表对来宾泄漏内部文档**：列表、最近更新、搜索结果三处 SQL 只判「已登录」，没有按角色判 `internal`，来宾能看到标题但点进去 404。现在改为按 `policy::can_view` 的结果过滤（内部账号才可见 `internal`）。
- **搜索绑参错位**：修复上述泄漏时引入过绑参顺序错误（`? = 1` 拿到搜索词），已修正，并补了「成员必须看得见自己的档案」的正向对照测试。
- **富文本链接加固**：URL 里出现反斜杠一律拒绝。浏览器会把 `/\evil.com` 归一化成 `//evil.com`，能绕过「以单个 `/` 开头即站内」的判断。

## 验证

- `cargo test`：247 个测试全绿（含本地 MySQL 集成测试），`cargo clippy -- -D warnings` 与 `cargo fmt --check` 均通过。
- 线上冒烟 18/18 通过；来宾访问档案列表不再出现内部文档标题。

## 升级方式

1. 备份数据库（`mysqldump`）。
2. 用本包的 `nexus`（Linux）或 `nexus.exe`（Windows）替换旧二进制。
3. `systemctl restart nexus`（或 `deploy/apply.sh`），确认 `/healthz` 返回 `{"db":"ok","status":"ok"}`。

本次**没有新增迁移文件**，已有数据库不需要任何手工操作。
