## 这一版做了什么

**Word 文档三个环节打通**：从 Word 复制粘贴不再带进一堆私有标记，可以直接上传 `.docx`，档案里能内嵌只读查看器。

### 上传 .docx

- 编辑器工具栏多一个「插入 Word」按钮，选文件即上传；也接受拖拽之外的文件选择。
- 服务端解包 OOXML（`zip` + `quick-xml`），把段落、标题、加粗/斜体/下划线、有序/无序列表、表格（`colspan`/`rowspan` 折算）、图片映射成受控 HTML。
- 图片不内联 base64：逐张落盘、内容寻址去重，同一张截图在十个文档里只存一份。
- 所有解析产物都再过一遍白名单净化器——解析器只是"生成 HTML 的另一个来源"，和用户粘贴没有区别。

### 站内查看器

- 上传时就把净化后的 HTML 存进 `media.html`，查看器 `GET /doc/{sha}` 直接渲染，**不再重新解析文件**（省 CPU，也避免"同一份文件两次解析结果不同"）。
- 内嵌用 `<iframe sandbox="">`（最严档：不允许脚本、不允许同源、不允许表单），地址只认本站 `/doc/{64 位十六进制}`。

### 粘贴清洗

- 前端把 Word 的 `mso-*` 样式、`<o:p>`、条件注释、`<style>` 块去掉，保留基本格式；
- 后端 `richtext::sanitize` 再扫一遍——前端清洗是为了不留垃圾，后端净化才是安全边界。
- 粘贴的图片走既有上传链路，不把 base64 塞进 HTML。

### 限制

| 项 | 上限 |
| --- | --- |
| .docx 文件 | 8 MiB |
| 解压后的 `document.xml` | 32 MiB（防解压炸弹） |
| 正文纯文本 | 60 000 字符 |
| 单张图片 | 8 MiB，每份最多 32 张 |

### 修掉的两个真问题

- `media.mime` 列宽按图片设计的 `VARCHAR(64)` 装不下 docx 的 72 字符 MIME，上传直接 `1406 Data too long`（表现为 500）。`0017` 放宽到 128。
- 富文本的实体解码原来是一串 `replace`，`&amp;lt;` 会被解两次变成真尖括号，等于绕过转义。改成单趟解码，并加测试钉死。

### 验证

`cargo test` 290 passed / 0 failed（含 4 条 docx 集成测试），clippy 与 fmt 均为 0。
